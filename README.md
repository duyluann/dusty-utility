> Quick Launch deployment

## Quickstart

```bash
git clone git@github.com:/dusty-utility.git
cd dusty-utility
./start.sh
```

## Services

- `traefik/` — Reverse proxy, TLS termination, HTTP→HTTPS redirect, root-domain landing page
- `kuma/` — Uptime Kuma
- `freellm/` — FreeLLMAPI

## Prerequisites

The target server must have:

- `git` — used by the deploy workflow to clone/pull the repo
- `docker` + Docker Compose plugin — container runtime and orchestration
- Traefik running with the `traefik-net` external Docker network

## Setup

`start.sh` automatically copies `.env.example` → `.env` for each service on first run.

To configure before starting, copy and edit manually:

```bash
for svc in traefik kuma freellm; do
  cp "$svc/.env.example" "$svc/.env"
  # Edit $svc/.env — set TRAEFIK_HOST, passwords, API keys, etc.
done
```

## Usage

Start all services:

```bash
./start.sh
```

Stop all services:

```bash
./stop.sh
```

## Deploy

The included GitHub Actions workflow is **disabled by default** to prevent failures before your server is configured.

To enable automatic deployment:

1. Configure the **Required Secrets** listed below in your GitHub repository (**Settings > Secrets and variables > Actions**).
2. Go to the **Actions** tab in your repository, select the **Deploy** workflow, and click **Enable workflow**.

### Required Secrets

| Secret | Description |
|---|---|
| `SERVER_SSH_PRIVATE_KEY` | Private SSH key for the runner to reach the server |
| `SERVER_IP` | Server IP address |
| `SERVER_DOMAIN` | Your domain, e.g. `myapp.com` — enables Traefik + TLS |

### Maintenance Workflows

If your repository includes governance workflows (like **Release** or **Update LICENSE**), they may require a `GH_PAT` secret (Personal Access Token) with `contents: write` and `workflows` permissions to run successfully.
